# POS システム(ラーメン店向けセルフオーダー)

ラーメン店を想定した、**席からの注文 → 厨房での調理管理 → 会計 → 売上の集計・CSV 出力**までを一通り扱う POS アプリです。

- デモ: https://ramen-pos-five.vercel.app/
- 売上ページ(`/sales`)はパスワード付きです。パスワードは0000

## 主な機能

### お客さん用画面(`/`)

- カテゴリ(すべて / ラーメン / サブメニュー / ドリンク)で絞り込み
- 商品ごとのオプション選択(麺の固さ・量などの単一選択、トッピングの複数選択)。追加料金を含めた合計を、選ぶたびに表示
- カート → 注文確認(個数を減らす、合計金額の表示)→ 注文番号の表示
- 注文履歴(その端末の、当日分のみ)
- 席番号は URL で指定(`/?seat=3` で3番席)

### キッチン画面(`/kitchen`)

- Firestore のリアルタイム購読で、注文が入ると即座に画面へ反映
- 注文の流れ: 未調理 → 会計待ち → 完了(またはキャンセル)
- 商品ごとの「完成」チェック。すべて完成すると「準備OK」が押せる
- 会計待ちの注文に合計金額を表示。キャンセルは確認ダイアログ付き
- 注文履歴(完了・キャンセル)の表示

### ディスプレイ画面(`/display`)

- オーダーと未会計の注文番号が表示される
- ※前に作ったハンバーガーショップの店頭表示ディスプレイの名残り。消しても問題無い。

### 売上画面(`/sales`)

- 日別 / 月別の切り替え
- 売上合計・会計済みの件数・客単価・キャンセル数
- 商品別の販売個数と売上(売れた順)
- CSV ダウンロード(Excel で文字化けしない形式)
- パスワード入力による簡易的な保護

### 開発用ナビ

- 席の切り替え、画面の切り替え、デザインの切り替え(オリジナル / 食券機をモチーフにしたデザイン)

## 工夫した点

### 計算ロジックを画面から切り離して、テストを書いた

金額の計算や集計は、画面のコードから `src/utils/` の関数に切り出し、Vitest でテストしています。

- `price.js` — オプションの平坦化、商品の合計、注文全体の合計
- `sales.js` — 売上・件数・客単価の集計、商品別の集計
- `csv.js` — CSV の文字列の生成
- `dateRange.js` — 「その日」「その月」の範囲の生成

分岐(`||` や `??` が分ける場合)ごとにケースを書き、**わざとコードを壊してテストが失敗することを確認**しながら作りました。

### 過去の売上が変わらないデータの持ち方

注文を保存するとき、商品ごとの小計と注文全体の合計(`totalPrice`)も保存しています。あとでメニューの値段を変えても、過去の売上は変わりません。`totalPrice` がない古い形式の注文は、商品から計算し直して集計します。

### 日付の範囲の扱い

- 「その日」は、0時から翌日の0時の手前まで(`>=` と `<`)で絞り、日をまたぐ境目の注文が、重複したり漏れたりしないようにしました。
- 月の範囲は、必ず1日を起点にして計算しています(31日から1か月進めると、翌々月に飛ぶことがあるため)。
- 日付だけの文字列から `Date` を作ると世界標準時になり、日本時間で9時間ずれるので、`T00:00:00` を付けて、その場所の時間で作っています。

### 非同期処理の競合への対処

売上ページで、日付や月をすばやく切り替えたとき、古い読み込みの結果が後から届いて、表示がずれないようにしています(`useEffect` のクリーンアップで、古い結果を捨てる)。

### CSV 出力

- カンマ・ダブルクォート・改行を含む値を、正しくエスケープ
- 先頭に BOM を付けて、Excel で日本語が文字化けしないようにした
- 金額は桁区切りなしの数値にして、Excel でそのまま集計できるようにした

### React の基本の徹底

- state を直接書き換えず、新しい配列やオブジェクトを作って更新
- `map` による繰り返し(タブ、集計項目など)
- 重複していた処理の関数化、モーダルのコンポーネント分割

### デザイン

AIが出力した食券機をモチーフにしたデザインを用意し、オリジナル（手打ち）のデザインと切り替えられます。

- ボタンは「押し込める」見た目、価格は光るドット表示、注文完了は食券の見た目
- タッチしやすい大きさのボタン、キーボード操作時のフォーカス表示、アニメーションを減らす設定への対応

## 制限事項と今後の改善

デモ・ポートフォリオ用として作ったため、次の点は簡易的な作りです。

- **売上ページのパスワードは、見た目上の保護です。** `VITE_` の変数はブラウザに送られるコードに含まれるため、値を読み取れます。また、Firestore のデータそのものを守る仕組みではありません。実運用では、Firebase Authentication によるログインと、Firestore のセキュリティルールによる制限が必要です。
- 注文番号は乱数で付けているため、まれに重複する可能性があります。日ごとの連番にする改善が考えられます。
- 通信に失敗したときの画面表示が、一部の操作で簡易的です。
